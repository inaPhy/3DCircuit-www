# 3D Circuit - 開発引き継ぎおよび移行仕様書

本ドキュメントは、3D回路シミュレータ（3D Circuit www）のこれまでの開発ノウハウと設計仕様をまとめた移行・引き継ぎ用のドキュメントです。
派生プロジェクト（3Dcircuit-AR など）の開発時に、これまでの経緯と実装意図を把握するためのガイドとして活用してください。

---

## 1. プロジェクト概要
HTML5、CSS3、Vanilla JavaScript、Three.js、および Math.js を使用した、ブラウザ上で動作する3D回路シミュレータです。
2Dで回路図を配置し、シミュレーションを開始すると電位の高さを3Dの「高低差」および「流れるパーティクル」で表現する視覚的な教育効果の高いツールとなっています。

---

## 2. これまでの主な改善とノウハウ

### ① 導線バリエーションの拡張（全11種）
*   **仕様**: 直線、L字、T字、十字の4形状に加え、それぞれの回転状態を考慮した全11種類のバリエーションを配置・編集可能です。
*   **UI/UX**: モーダルウィンドウ内でグリッド状に視覚的に選択可能。直線（0/180度、90/270度など）や十字の対称性による無駄な選択肢を排除し、スマートに選択できるハイライト正規化ロジックを実装しています。

### ② モバイル・タッチ操作対応の最適化
*   **ダブルタップガード**: タッチ操作時にダブルタップで編集モーダルが即時に閉じてしまう不具合を防ぐため、500msのタッチガードロジックを導入しました。
*   **レスポンシブCSS**: スマートフォンの縦画面でモーダル内の導線選択アイコンが枠からはみ出さないよう、CSSでGrid配置、アイコンサイズ、およびモーダルの `max-width` を最適化（380pxに調整）しています。

### ③ シミュレーション制御ロジック
*   **パラメータ保存時の自動停止**: 回路の接続関係（トポロジー）に影響する「導線形状・向き」が編集モーダルから変更された場合、安全のためシミュレーションを自動で一時停止（Editモードへ移行）させます。数値（抵抗値や電圧など）の変更のみの場合は、シミュレーションを継続したままリアルタイムで反映します。

### ④ 定常状態（DC）ベースのGND底上げロジック
*   **背景**: 複数電源がある回路などで電位が負になり、3D表示で回路が地面（Z=0）より下に埋まる問題がありました。
*   **解決策**: 毎フレームの電位で底上げを行うと、交流回路やコンデンサの過渡現象で地面が激しく揺れ動く（バウンシング）問題が生じるため、「回路構成の変更時（開始時）に一度だけDC解析を行い、その最小電位をGND（0V）基準として以降のステップで差分適用する」方式を導入しました。

## 3. 主要ファイルの構成と役割

| ファイル名 | 役割・概要 |
| :--- | :--- |
| `index.html` | UIの骨組み、上部パーツツールバー、パラメータ編集用モーダル、グラフエリアなどのDOM構造を定義。 |
| `style.css` | UI/UXのスタイリング。レスポンシブ対応（スマホ縦画面向け設定など）、各種テーマカラー定義。 |
| `main.js` | UIのインタラクション、ドラッグ＆ドロップ、アニメーションループ、およびGND底上げ用のオフセット処理を管理。 |
| `simulator.js` | 修正節点解析法（MNA: Modified Nodal Analysis）を用いた回路計算コア。過渡解析やDC解析などを実行。 |
| `simulator3d.js` | Three.jsを用いた3Dビューア。パーツの3D化、電位のZ軸高さ反映、電流パーティクルのアニメーションを制御。 |
| `settings.ini` | アプリケーションの初期構成設定（十字導線の表示フラグ `show_wire_cross` など）。 |
| `version.js` | アプリケーション、保存形式、Service Workerキャッシュのバージョンを一元管理。 |
| `manifest.webmanifest` / `service-worker.js` | タブレット・スマートフォン向けPWAのインストール情報とキャッシュ制御。 |
| `manual/` | アプリケーションの取扱説明書。アップデート履歴も記載。 |

## 4. 派生開発（AR化など）に向けた技術的な留意点

1.  **3DビューとARの統合**:
    *   `simulator3d.js` は Three.js に依存しています。AR化にあたっては、WebXR Device API または `AR.js` / `model-viewer` / `A-Frame` などのARライブラリと組み合わせる必要があります。
    *   カメラフィードとThree.jsの `WebGLRenderer` を合成し、現実世界の平面（マーカーやアンカー）の上に回路の3Dメッシュ（`simulator3D.scene`）をマウントする構成が考えられます。
2.  **電位の高さメタファー**:
    *   現実世界のテーブル等の上に回路を表示する際、GND底上げロジック（`simulationGroundOffset`）はそのまま有効に機能します。最も低い電位の部分がテーブル表面にピタッと接地するようになります。
3.  **UI/UXの移行**:
    *   ARモード時は、2D画面のツールバーやドラッグ＆ドロップ操作をAR空間上のインタラクション（レイトレーシングによるタップ、ジェスチャー、または画面オーバーレイUI）に移植する必要があります。

## 5. バージョン管理ルール

* 現在のアプリケーションバージョンは `version.js` の `number` で管理します。
* 保存JSONの互換形式を変更した場合のみ `storageFormat` を更新します。
* 配布ファイルを更新した場合は `cache` も更新し、端末に残る旧Service Workerキャッシュを切り替えます。
* リリース時は `manual/index.html` のアップデート履歴に日付と変更内容を追加します。
